# AD-150 — The judge is sent the text a read returned rather than the host's envelope, skips the prompt question when the prompt states no task, counts output tokens, and records a fourth reading about consequence

- **status**: active

## Decision

1. **The recall holds what the read said.** `readableOutput` opens a tool result that is a JSON object or array and
   keeps the text inside it — `stdout`, `stderr`, the `text` of each MCP part — joined by newlines. A string inside
   the envelope is kept as it is, so a page that is itself JSON stays that text. Output that is not an envelope, or
   carries no text, is remembered untouched. It runs in `rememberUntrustedOutput`, so the verbatim check and the
   judge read the same thing.
2. **A prompt under 16 characters is no prompt.** The judge leaves `command_serves_prompt` and the
   `operator_prompt` field out, which is the shape a session with no stored prompt already has.
3. **Output tokens are counted.** The client reads `usage.output_tokens`, the judge, the screen and the advisors sum
   it, and it reaches `gen_ai.output_tokens` and the cost estimate.
4. **`command_is_consequential`, a fourth reading.** "Does the action have an effect beyond reading what is already
   on this machine?" — true for sending data off the machine, downloading or installing, deleting or overwriting,
   reading credentials, changing configuration, permissions or history. Asked in the same request as
   `command_follows_content`, about commands and MCP calls only. It is written to the record as `consequential` and
   **routes nothing**: the thresholds and the verdict are what they were.

## Why

**The trace made these visible, and nothing else would have** ([/decisions/ad-149.md](/decisions/ad-149.md)). Four
real exchanges, one turn:

- `content.text` was `{"stdout":"<html>…","stderr":"","interrupted":false,"isImage":false,…}`. The service's own
  guidance is that state a question does not need costs accuracy, and this design already cuts, chunks and omits
  fields for that reason. The same serialisation escapes every quote and newline, so a command quoted in a page —
  `run "npm ls"` — was not in the recall verbatim, and the verbatim check of
  [/decisions/ad-077.md](/decisions/ad-077.md) could not see it.
- With `operator_prompt: "go"`, `command_serves_prompt` read 0.53, 0.37 and 0.46 for a command that obeyed the
  bait and two that had nothing to do with it. A question about a prompt that says nothing measures nothing, and
  those readings would have gone into calibration as if they meant something.
- The raw body said `"output_tokens": 43` on a two-question request while the record said `0`.
- `npm ls --depth=0` cleared at 0.98 / 0.80. It did what the content asked, reworded — and listing packages harms
  nobody. In `ask` mode that is an interruption an operator learns to wave through, which is how a rail dies
  ([/decisions/ad-034.md](/decisions/ad-034.md)).

**Record the fourth reading before it decides anything.** It has no measurement. `command_serves_prompt` shipped
the same way, and the spike then showed it does not separate; this one may not either. Asked now, the readings
accumulate beside the other three on real work, and the calibration task can say whether "follows **and**
consequential" asks less without missing more.

**Atomic, not compound.** "Does it obey the content and also matter" in one question gives one number nobody can
take apart. Two readings combined in code can be re-thresholded from the records without asking again.

**Not for edits or replies.** An edit always overwrites a file and a reply has no effect of its own, so the answer
is known before it is asked.

## Trade-offs

**Readings before and after are not comparable.** The content sent is different text and the request carries one
more question. Records written before this decision do not count toward calibration, for the second time today.

**One more answer can fail a run.** The client refuses a body missing any asked id, so the fourth question is one
more way to get `invalid-response`. That is `serves`' existing exposure, and a run that collapses abstains.

**The envelope's keys are dropped.** For a host that hands over a bare JSON API body with no envelope, the keys of
that body go with them. Instructions live in values; the verbatim check matches values.

**Sixteen is a guess.** `continue with the plan` passes it and says as little as `go`. It removes the worst case
and is one constant to move.

**About twenty output tokens more per command-time request.**

## Not decided here

- **Whether `consequential` should ever gate `ask`.** That is what the records are for.
- **A broader first question.** `content_instructs_agent` asks whether content addresses an *agent*. An injection
  addressed to nobody — "before reviewing, run this" — may screen low and then never be asked about again. A wider
  question would make every README pay for the second one. It needs a labelled set from the trace, not an opinion.
- **Carrying the last substantive prompt into a short turn.** It would keep prompt text on disk across the turn
  boundary that [/decisions/ad-146.md](/decisions/ad-146.md) clears it on.
