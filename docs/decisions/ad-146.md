# AD-146 — the untrusted-content judge asks about rewritten commands, over the network, and only ever asks

- **status**: active

## Decision

1. **`untrustedContent.judge`**, a nested config block, default off: `enabled`, `mode` (`record` | `ask`,
   default `record`), `thresholds.contentInstructsAgent` (0.50) and `thresholds.commandFollowsContent`
   (0.55), `timeoutMs` (2500), `concurrency` (8), `maxEntryChars` (8000), `maxOperatorPromptChars` (4000),
   and a pinned `model` (`jev-1.13.0`). Merged three levels deep in `policy.loader.ts`, because
   `thresholds` is its own object and a two-level merge would drop a sibling threshold to `undefined`.
2. **`src/platform/typesafe.ts`** — a dependency-free System One client on native `fetch` and
   `AbortController`. One `timeoutMs` covers the request and every retry together. 429 and 529 retry through
   `platform/backoff.ts`'s `nextDelay`; 400, 401, 403 and 422 never do. A body that is not JSON, a missing
   answer, a `type` other than `noul` or a non-finite `noul` is refused as `invalid-response` rather than
   coerced. It returns a discriminated result and never throws to its caller.
3. **`src/core/untrusted/untrusted.judge.ts`** — one request per recall entry, or per chunk of an entry above
   `maxEntryChars`, at most `concurrency` outstanding, inside the one budget. Three `noul` questions are sent
   and two of them route: `content_instructs_agent` and `command_follows_content` must both clear their own
   threshold. `command_serves_prompt` is asked and recorded and routes nothing.
4. **`src/core/untrusted/untrusted.prompt.ts`** — the turn's operator prompt, persisted per session,
   truncated at `maxOperatorPromptChars`, written only while the judge is enabled and cleared on the same
   turn boundary that already clears the recall and the framing marker.
5. **The call site is `tool-before.ts`'s shared prelude, on `shell.before` only**, immediately after
   `askIfFromUntrusted` — the first `await`-capable seam after the verbatim check, since `handleShellBefore`
   is synchronous.
6. **The verdict is `ask` or nothing**: `{ kind: "ask", rule: "untrusted-judge", reason, diagnostic }`, where
   `reason` names the highest-scoring entry's source and never its text, and `diagnostic` carries all three
   probabilities and the answering model.
7. **The key is read from `TYPESAFE_API_KEY`, else from `credentials.json` under the machine home**, and from
   nowhere else. With neither, no request is made and the run is recorded under the `auth` category.
8. **Every run that made a request is recorded** as `policy.observe` with `rail: "untrusted-judge"`, its usage
   in `gen_ai`. `tlc harness obs report` gains a judge section; `doctor` reports the judge when it is enabled
   and inert, when its config cannot be read, and when more than 30% of the last 50 runs failed.
9. **A judge field whose value cannot be read switches the judge off and names itself.** `loadPolicy` runs
   inside every hook, so it does not throw.

## Why

**The gap is stated in the rail's own catalog entry**, not inferred: "verbatim because a paraphrase cannot be
shown to come from the content, so a rewritten command is missed" ([/decisions/ad-077.md](/decisions/ad-077.md)).
Agents paraphrase by default, so the ordinary case is the uncovered one, and a miss leaves no record at all —
nobody could have counted how often it happens. A spike measured two commands that pass both the floor's
eight rules and the verbatim check: an exfiltration piped through `curl`, and `rm -rf ./ --no-preserve-root`
reached from a migration guide, which the floor allows because the target resolves inside the project.

**`docs/concepts.md` declined advisory checks because they need the network, and that reasoning still holds
for a check that is on by default.** This one is off by default, and disabled is indistinguishable from
absent: no prompt is stored, no state file is created, no request is made and no record is written, so an
operator who upgrades and opts out spends exactly what they spent on v0.16.2. A test proves the no-op rather
than a comment claiming it.

**`ask` and never `deny`, because inference is still inference.** TypeSafe states that this class of filter is
not a security boundary, and the jaggedness page for `jev-1.13` states that the model does not treat its state
as hostile — so content that argues for its own classification can move the answer. A `deny` would be an
authority the mechanism cannot carry, and an injection that talks the judge round returns the harness to the
behaviour it already has. This is also what keeps AD-077's reasoning intact: the verbatim check asks because
provenance cannot be proven, and a probability does not prove it either.

**One request per entry, because the documented failure is accuracy loss as the state fills with material the
question does not need.** A 64,000-character recall in one request is that failure by construction. Measured
from Dublin against the US West Coast: p50 303 ms, p95 600 ms, max 845 ms for a single request, so
`concurrency: 8` puts a whole recall in one wave at roughly the single-request p95 — which is what the added
latency target was written to mean. `timeoutMs` is sized to what an operator tolerates before every shell
command, not to the 10 s the host permits: three seconds of wait gets a rail switched off within a week
([/decisions/ad-034.md](/decisions/ad-034.md), [/decisions/ad-012.md](/decisions/ad-012.md)).

**Fail open, and never silently.** A network fault on a third-party service must not stop an operator's
command. But a control that is inert without saying so is worse than no control, so every error, timeout and
unusable body is recorded under its category, and one failed request collapses the whole run rather than
producing a verdict over a recall the judge only partly saw
([/decisions/ad-076.md](/decisions/ad-076.md)). The same invariant holds at the aggregate: a service that
slows down converts the judge into a rail that checks nothing while still reporting as enabled, so `doctor`
names it degraded once the failure share over the recent window crosses 30%.

**The key cannot come from the environment alone.** Measured on 2026-09-19: `ps eww` on the host process that
parents every hook showed zero occurrences of `TYPESAFE_API_KEY` while `PATH` showed one in the same dump, so
the zero was the fact and not the method failing. A hook inherits the host's environment and no host passes an
arbitrary variable through, so an environment-only rule would have shipped a capability nobody could switch
on. The machine home is the plane `model-prices.json` already uses: machine state, never versioned, outside
any repository. A project config field stays rejected — it puts a live credential in a file git tracks.

**Record mode belongs to the judge rather than to `observe`.** `ObserveVerdict` carries a violation count and
whether prose was injected, and the judge has no injected prose, so neither field would mean anything for it
([/decisions/ad-027.md](/decisions/ad-027.md)). Record mode still makes the call and still pays, which is the
point: a shadow that does not pay the real cost does not measure it.

**The thresholds are a direction, not a calibration.** They come from 20 synthetic cases their own author
wrote: at 0.50/0.55 the judge asked on 9 of 10 paraphrased injections and on none of 10 hard benign cases,
while the placeholder 0.70/0.80 cost three of those ten for no gain in false asks. Twenty authored cases
cannot establish a false-ask rate an operator will live with, and the only independent evaluation of this
model covered twelve texts. So the judge ships in `record` mode and `ask` is not recommended to anybody until
per-question calibration curves come from real readings.

## Trade-offs

**Data leaves the machine, and that is not revertible.** The code is a revert away; the text of issues, pages
and MCP results, the operator's own prompt and the proposed command, once sent to a service in the United
States, are not. `secrets.redactOutput` runs over all three before assembly, the local record carries the
source rather than the text, and the trade-off is stated in full in the capability catalog — because the
consent being asked for is not "turn on a rail", it is "send this to a third party".

**Money per check, and latency on every shell command in a session that read anything external.** Measured at
about US$0.03 per 1,000 checks, and 600 ms p95 per request. That latency figure is a floor rather than a
ceiling: it was taken four days after the model's launch, against a service in early access, so the load on
it is more likely to be light than heavy today. The budget is configuration rather than a constant for
exactly that reason.

**A judge in record mode costs money and interrupts nobody.** That is deliberate and it is still a cost an
operator pays before getting any protection from it.

**`command_serves_prompt` is paid for and routes nothing.** One question's tokens per request, recorded so
calibration can decide whether it belongs at all.

**The degraded window and share are constants, not config.** 30% of the last 50 runs is a number nobody has
tuned against real data. An operator who disagrees cannot change it without changing the code.

**Chunking attributes a reading to an entry, not to a position inside it.** A chunk that clears the thresholds
is reported as its entry clearing them, so an operator learns which source rather than which passage.

## Not decided here

- **Whether `ask` mode should be offered at all.** That is the calibration task's verdict against the stated
  recall and false-ask targets. The config accepts `ask` today because an operator who reads the trade-off may
  choose it; nothing recommends it.
- **The calibrated thresholds, and whether a fourth question is needed.** The spike found one shape neither the
  judge nor the floor covers — content asserting a destructive step as a precondition rather than instructing
  an agent, which scored 0.31 on `content_instructs_agent` correctly, by the question's own wording. Widening
  the first question is the wrong fix: two benign cases scored 0.98 on `command_follows_content` because a
  README legitimately said to run something.
- **Writes, edits and MCP calls on `tool.before`, and an output gate on `response.after`.** A different
  question set and a different notion of "derived from"; the output gate also needs the response text
  persisted and has no recall to anchor to.
- **Persistent caching of responses.** The same command against the same recall is rare enough that a cache
  would mostly hold entries nobody reads again.
- **A second judge implementation behind an abstract interface.** Worth paying for if calibration fails after
  the rail has shipped to operators; today there is one consumer, the rail is default-off, and the swap costs
  one module.
- **Whether `docs/coverage.md`'s ASI01 limit changes.** It still states the rewritten-command gap, which is
  still true for every operator who has not opted in and while `ask` is not recommended.
- **Who writes the init wizard's opt-in copy.** The catalog's `tradeOff` is the text; whether the wizard
  reuses it verbatim is not settled here.
