# AD-156 — Antigravity is a provider whose every harness failure is a refusal

- **status**: active

## Decision

1. **The host event arrives as an opaque argv token.** The wiring writes `node <launcher> <handler>
   antigravity:<Event>` for `PreToolUse`, `PostToolUse` and `Stop`. `run.ts` reads `argv[2]` without
   interpreting it and passes it as the new optional second argument of `ProviderPort.toEvent(raw, hostEvent?)`.
   Only the adapter knows the `antigravity:` prefix; any other token, bare or absent, translates to `null`.
   The prefix exists because the three bare names are also Claude Code's event names, and a bare token would
   let a hand-written Claude hook select this host's posture. `src/core/` and `src/contracts/` receive no host
   event name and no native tool name; the host's `Stop` reaches core only as the canonical `stop`.
2. **A per-host exception to [/decisions/ad-101.md](/decisions/ad-101.md), for `antigravity` only.** The port
   gains an optional `failClosed` posture (`hostEventPrefix`, `failureResponse(cause)`, `diagnosticRoot`).
   `run.ts` picks the owner from the token prefix *before* reading stdin, so broken stdin still has an owner.
   With an owner, every failure renders `{"decision":"deny","reason":"tlc-harness: <cause>"}` with exit 0,
   for the causes `launcher-error`, `timeout`, `invalid-stdin`, `unrecognized-payload` and `handler-error`.
   The launcher duplicates that literal because it runs when the TypeScript runtime cannot: under the prefix
   it holds the child's stdout, kills the child at 8 s, 8 s or 118 s (two seconds under the wired 10, 10 and
   120), and passes through only a single allow or deny object. The reason carries no path, env or parse
   detail; the detail goes to stderr, and a diagnostic reaches disk only under `workspacePaths[0]`, never
   under the hook's working directory. Without the prefix, both paths are the 0.16.2 code, line for line.
3. **The render map.** `abstain`, `allow`, `context`, `continue` and `rewriteOutput` render
   `{"decision":"allow"}`; `deny` renders deny with its reason; `ask` and `rewriteInput`, which this host has no
   channel for, render deny with their reason. `{}` and empty stdout are never produced. `ask`, `force_ask`,
   `deny_unless_prior_grant`, `permissionOverrides` and `continue` on `Stop` are declared unsupported.
4. **The tool table** lives only in `src/providers/antigravity/antigravity.tools.ts`: `view_file` → `Read`
   (`read.before`), `write_to_file` → `Write`, `replace_file_content` → `Edit`, `multi_replace_file_content` →
   `MultiEdit` (marked unverified, path only), `run_command` → `shell.before`/`shell.after` with `Cwd`, and
   `invoke_subagent` → `Task` with the subagent type only when exactly one is spawned. Any other tool passes
   under its native name.
5. **Two new protected wiring targets, for every provider.** `wiringTargets()` returns the global
   `~/.gemini/config/hooks.json`; the new optional `projectWiringTargets(projectDir)` returns
   `<projectDir>/.agents/hooks.json`. `composeProtectedPaths` in `run.ts` joins both across the whole registry,
   so a `Write`, `Edit` or `MultiEdit` to either file from a Cursor or Claude session is now `wiring-tamper`
   too. This is intentional. Because the policy-surface check reads the same list, a shell command naming
   either path with a verb that is not a proven reader is also refused — on this host that includes
   `Get-Content ./.agents/hooks.json`. The floor's own files and rule text are unchanged.
6. **Recovery, then last resort.** Install and doctor print, whenever the group is in place, that an
   unverified surface may deny every tool; that the primary recovery is to remove only the `tlc-harness` key
   from the global file outside `agy`, or delete the file when it is the only key; and that
   `tlc harness uninstall --yes` is the last resort because it also removes the Claude and Cursor harness hooks,
   the `harness-init` skill links, `tlc` from PATH and the runtime directory.
7. **Stop without deduplication.** The Stop handler runs on every `Stop` received. The proposed
   `conversationId` + `fullyIdle` key would not have prevented the observed double Stop (the two differ in
   `fullyIdle`) and would have silenced later turns of the same conversation.
8. **`named-group` and `presencePath`.** `ProviderWiring.strategy` gains `named-group` — one root key belongs
   to the harness and the rest of the file to the operator — and an optional `presencePath`. The host counts as
   installed when `~/.gemini/antigravity-cli` exists, not when the shared `~/.gemini` directory does. Install
   writes only the global group; it never writes the workspace `.agents/hooks.json` nor the CLI's
   `settings.json`.
9. **Number 156.** Two open branches each use 146 to 150 for different records; whichever merges second
   renumbers to 151–155. 156 survives both landing first, in either order, and `check-decisions` does not
   require contiguous numbers.

## Why

**The host inverts the failure shape the harness was built on.** Measured with `agy` 1.2.13 on Windows: a hook
that prints nothing lets the tool run, and a hook that prints `{}` blocks it. The fail-open rule of
[/decisions/ad-101.md](/decisions/ad-101.md) prints `{}` precisely so a broken harness gets out of the way —
on this host that same `{}` blocks every tool, while a crash that prints nothing silently opens the floor.
Neither outcome is a choice anyone made. An explicit deny that names its cause is the only failure output
that means the same thing to the host and to the operator reading it.

**The token, not stdin, decides the owner.** A fail-closed posture that is chosen by parsing stdin cannot
cover the case where stdin does not parse. The prefix is in the command the install wrote, so it is known
before a byte is read.

**Abstain has no neutral spelling here.** Empty stdout is permission to this host, so the only honest
rendering of "no opinion" is the explicit allow the host would have inferred anyway. The provider
conformance test "abstain never renders anything that reads as an approval" matches the Cursor and Claude
approval keys and does not catch this shape; that is known and accepted, not an oversight.

**The workspace file is the host's own wiring surface.** An agent that can edit `.agents/hooks.json` can
disable the hook that constrains it, and that is true whichever editor the agent runs in.

## Trade-offs

**A surface nobody measured can deny every tool.** The global file is shared by the CLI, the IDE (2.0.2) and
the app (2.18.1). If one of those, or a CLI newer than 1.2.13, fires the group with a payload the adapter does
not recognise, every tool there is refused with `unrecognized-payload` or `invalid-stdin`. The doctor cannot
see a surface that never fires, so the warning and the one-key recovery are printed on every install and every
healthy doctor run instead of once.

**Stop work may run twice per execution loop.** Accepted until a spike measures multi-turn Stop.

**A grandchild of the Stop gate may outlive the refusal.** The launcher answers on time and exits; its kill
reaches only the direct child.

**`allow` is not the host's permission.** In headless mode an explicit allow did not bypass the CLI's own
command permission prompt. Its effect in an interactive session was not measured.

**Cursor and Claude sessions gain two refusals they did not have**: writes to either Antigravity hooks file,
and shell commands that name them without a proven reader.

## Not decided here

- **Hooks inside a subagent, multi-turn Stop, and interactive `allow`.** Each needs its own spike before the
  corresponding gap closes.
- **The IDE 2.0.2 and the app 2.18.1** as floor-enforcing surfaces. The floor is claimed for the CLI only.
- **The same group name in the global and the workspace file.** Two differently named hooks both fire; the
  same name in both, and `enabled: false` in the workspace file overriding the global group, were not measured.
- **Roots beyond `workspacePaths[0]`** in a multi-root workspace are not protected.
- **PowerShell destructive cmdlets** such as `Remove-Item` are outside the floor's POSIX verb list, and a
  relative path is resolved against `projectDir`, not the command's `Cwd`.
- **Rebasing onto the provider-kind contract** of the open providers branch: `named-group` would become a
  `kind` there, with that branch's backup-before-overwrite rule applying to this writer. The number stays 156.
