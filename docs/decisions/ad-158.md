# AD-158 — Codex exec 0.159.3 is a provider, and a hooks.json on disk is not the floor

- **status**: active

## Decision

1. **The claim is one executable.** `codex exec` of `codex-cli 0.159.3`, SHA256
   `57E1BDAB42C0559A74558CA17E85D5C7893CAA5F1E582F67E9DDD6D97FA705A7`. The interactive CLI, the desktop app, and
   the IDE extension stay `unverified`.
2. **The refusal is one object, with exit 0.** On `PreToolUse`, empty stdout, `{}`, non-JSON, exit 1, and exit 2
   leave the tool running. The block is
   `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"<reason>"}}`.
   `allow` and `abstain` write zero bytes. A harness failure (`launcher-error`, `timeout`, `invalid-stdin`,
   `unrecognized-payload`, `handler-error`) writes that same object with the cause as the reason, not exit 2.
   Kinds this host has no channel for write the same object with reason `unsupported`.
3. **No stdin keys are named.** `detect` returns `false` for every value. `toEvent` returns `null` for every
   record and every host-event string. `diagnosticRoot` returns `null`. The tool table is `Bash`,
   `collaborationspawn_agent`, and `collaborationwait_agent`, and `fill` copies nothing.
4. **The wiring target is a path, not a write.** `hooks.json` under `CODEX_HOME` when that variable is a
   non-empty string, otherwise under `~/.codex`. `strategy` stays `replace`. The provider does not write the
   file or `config.toml`. Doctor reports `not installed` when the file is absent, and one warning when it is
   present: `Codex hooks.json is present and this check does not call it installed wiring.` It never reports
   that file as wired. The shared writer skips a present file: it does not refuse it, does not exit non-zero
   because of it, and does not change its bytes with or without `--force`. Cursor, Claude, and Antigravity in
   the same invocation still follow their own writers.
5. **The path is protected in every session.** `wiringTargets()` returns that one file, so the existing
   `composeProtectedPaths` includes it when the active provider is Cursor, Claude, or Antigravity. That
   inclusion is not a `wiring-tamper` claim for Codex.
6. **`src/core/floor/` is unchanged.** This provider does not add `floorHostFacts`, `canonicalWiringMatch`, or
   `projectWiringTargets`. The package version stays `0.16.2`.

## Why

The capture on that pinned executable showed that a `hooks.json` on disk is not enforcement. Without hook trust
and without `--dangerously-bypass-hook-trust`, the hook is skipped and the tool still runs. That state is
`floor inactive`, and the flag does not persist. Exit code 2 on `PreToolUse` also left the tool running. An
adapter that fails in silence, or that prints another host's `{decision, reason}` object, is not a floor here.
Treating a present file as installed wiring would tell an operator the floor is on when the host ignored it.

The writer had the opposite bug. A present file without the harness marker made the shared replace path return
`refused`, the process exit non-zero, and the update path print that the hooks were unchanged and should be
forced. Cursor, Claude, and Antigravity in that same invocation failed with it. Skipping the Codex path leaves
their results alone and leaves the bytes alone.

## Trade-offs

- **`replace` plus a name guard, rather than a fourth `strategy`.** `merge` and `named-group` already belong to
  the Claude and Antigravity checkers. A new strategy would spread Codex into those checkers. The guard in
  doctor and the two skips in the writer are local, and the Cursor refuse path stays for a Cursor file.
- **No parser.** A fixture with named stdin keys does not exist. Returning `true` or a classified event would
  invent a field. The end-to-end proof prints the deny bytes from a test hook. It does not call `toEvent`.
- **The launcher table does not learn the prefix.** That table's verdict is `{decision, reason}`. This host
  does not block on that object, and `{}` leaves the tool running. The prefix lives on `failClosed`, which
  `run.ts` already reads. A `tlc-exec` crash under `codex:` still writes `{}`. This feature does not install
  that hook.
- **`continue` uses the same deny object with reason `unsupported`.** Silence on that kind would let the tool
  run. It is not a new channel.

## Not decided here

Stdin keys. Precedence of `hooks.json` against `[hooks]` in `config.toml`. A Codex `wiring-tamper` deny.
`harness_floor` for host `codex`. Surfaces outside `codex exec` (interactive CLI, desktop app, IDE extension).
Deny on `PostToolUse`. Deny on `Stop`. Deny by hook timeout. Managed `requirements.toml` and hash trust via
`/hooks`. Whether a child `session_id` equals the parent `session_id`.
