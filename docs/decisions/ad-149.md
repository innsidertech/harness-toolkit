# AD-149 — An opt-in trace keeps every exchange with Jev, as sent and as answered, in a file of its own

- **status**: active

## Decision

1. **`trace`, a boolean on both Jev blocks** — `untrustedContent.judge.trace` and `intelligence.jev.trace`, each
   `false` by default and each its own switch. A value that is not a boolean is a config error like any other in
   those blocks.
2. **Written by the transport, not by the callers.** `askWithinBudget` in `src/core/jev/jev.transport.ts` is the
   one place every request passes through, so the read-time screen, the command-time judge and the four advisors
   are traced by the same code. Each caller names itself: `judge:read`, `judge:command` (or `edit`, `mcp`,
   `response`), `advisor:<use>`.
3. **One record per request**, in `jev-trace.jsonl` under the project's state directory: the time, the session,
   the caller, the request's position in its run, the **request body as sent**, **every HTTP answer as it
   arrived** — status and body, retried `429`s included — and the **result the client read from them**, which is
   what the caller routed on. A request the budget never let out is traced with no HTTP answer, because that is
   what happened.
4. **The client gains an observer, and reads an error body only for it.** `askSystemOne` takes an optional
   `observe`. Without one it behaves exactly as before and never reads the body of a refusal.
5. **`tlc harness obs jev [n] [--full] [--json]`** renders the newest `n` exchanges (20 by default): the state, each
   question beside its answer, the outcome. The terminal cuts long fields unless `--full`; an uncut markdown copy
   with the raw bodies is written to `reports/jev-exchanges.md` in the same state directory.
6. **Bounded.** At 8 MB the file is rewritten to its newest 200 records.
7. **The obs records do not change.** `policy.observe` stays sources, probabilities and metrics, trace on or off.

## Why

**A mechanism nobody can watch cannot be trusted, and cannot be calibrated either.** The judge is new. Its record
says `instructs 0.97, follows 0.90`, and an operator deciding whether to believe that has to see what text was
scored, what question was put, and what the service said back. [/decisions/ad-146.md](/decisions/ad-146.md) kept
the text out of the record because a record is permanent, spooled across repositories and read by reports; none of
that is a reason an operator may never look.

**A file of its own, because the exposure is of its own kind.** The trace holds what the obs plane refuses to:
content from outside, the operator's prompt, gate output, the agent's reply. Keeping it apart means the spool, the
rollups and every report stay free of it, deleting it is `rm` of one file, and nothing downstream has to learn to
skip a field.

**At the transport, because that is where "everything sent" is true by construction.** A trace written by each
caller is a trace the next caller forgets. The transport already exists so that a second caller does not depend on
the first ([/decisions/ad-148.md](/decisions/ad-148.md)).

**As sent, so already masked.** Every caller masks secrets unconditionally before it builds a request, and the key
travels in a header that is never part of a request. The trace is therefore exactly what the third party received,
which is also the honest answer to "what left my machine".

**The raw answer beside the parsed one.** The client refuses rather than defaults, so a body it could not read
becomes `invalid-response` and one line. When that happens the body is the whole diagnosis.

## Trade-offs

**The sent text is now on disk, in the clear apart from masked secrets.** That is the feature and the cost. It
sits in the state directory, which git ignores, and it is off until an operator turns it on — a policy change they
accept from their own terminal like any other.

**An agent in the session can read the file.** It could already read the recall the content came from, so the
trace adds the operator's prompt — which the agent was given — and the scores. An agent that reads its own scores
could learn to word a command under a threshold. The judge only ever asks and is documented as not a security
boundary, so this lands where [/decisions/ad-146.md](/decisions/ad-146.md) already stands; it is a reason to keep
the trace for watching and not leave it on.

**Two switches.** One per block, because each block is its own consent about what leaves the machine, and an
operator watching the judge has not asked to keep gate output.

**With an observer, a refusal's body is read inside the request's budget.** A few milliseconds, only while tracing.

## Not decided here

- **A trace that redacts the content but keeps the questions.** It would not answer the question this exists for.
- **Retention by age.** The bound is size; `obs prune` does not touch the file.
