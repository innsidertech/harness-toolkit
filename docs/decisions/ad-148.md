# AD-148 — Jev is asked about four of the harness's own judgement calls, beside the rule that already makes each, and changes none of them

- **status**: active

## Decision

1. **`intelligence.jev`** — one block, off by default, with four uses that are each `off` by default:
   `lessonRank` (`off | record | apply`), `shipClaim`, `commentNarration` and `stagnation` (`off | record`). It
   carries its own `model`, `timeoutMs`, `concurrency` and `maxChars`, with the judge's transport defaults.
2. **`src/core/advisor/`** — `advise` puts one use's question to Jev about each item, one request per item, inside
   one `timeoutMs` for the whole call. It never throws and never decides: it returns readings. One unusable
   answer fails the whole call, so no caller ranks or compares over a partial set.
3. **The four questions and where they are asked:**
   - `lessonRank`, on `stop` when a gate fails — "does `lesson` address the problem shown in `failure_output`?",
     about the first 12 unpinned lessons of the selector's own ranking.
   - `stagnation`, on `stop` when a gate fails — "do `previous_failure` and `current_failure` report the same
     underlying problem?". The previous tail is kept per session, and only while this use is on.
   - `shipClaim`, on the reply — "does `agent_response` claim that the work is finished or verified?", about the
     end of the reply.
   - `commentNarration`, on an edit — "does `comment` only restate what the code next to it does?", about at most
     six comments the comment rule already flagged.
4. **Every record is a comparison.** A call is written as `policy.observe` with `rail: "jev-advisor"`, the use, the
   scores by item id, and what the existing rule decided — the selector's order, whether the pattern saw a claim,
   how many comments the rule flagged, the fingerprint's hit count. Never the text that was sent.
5. **`record` changes no decision.** Only `lessonRank: "apply"` does: scored lessons are ordered by their reading,
   unscored ones keep their rank below them, and pinned lessons are untouched.
6. **`src/core/jev/jev.transport.ts`** holds what every use of Jev shares — where the key comes from, and one
   wall-clock budget over a bounded fan-out. The judge imports it; nothing imports the judge to reach it.
7. **Secrets are masked before anything is sent, unconditionally**, and text is cut at `maxChars` first.
8. **`doctor` names the block when it is enabled and inert** — every use off, no key, or a value that cannot be
   read, which switches the block off rather than the policy load. `obs report` counts runs and failures by use.

## Why

**The judge showed the pattern works and what it costs; these are the places it fits.** Each of the four is a
question a regular expression answers badly and a person answers at a glance: relevance, a claim, narration,
sameness. Each is already decided by something in this harness, so the model's reading can be compared with a
decision that exists rather than trusted on its own.

**Record first, because nothing here has been measured.** The judge's thresholds came from twenty cases its author
wrote, and [/decisions/ad-146.md](/decisions/ad-146.md) calls that a direction and not a calibration. These four
questions have not had even that. A reading written beside the rule's answer, on real work, is the only thing that
can say whether the model does better — and until it does, replacing a rule that is at least deterministic with a
number nobody has checked would be a regression that looks like progress.

**`apply` only where a wrong answer is cheap.** A lesson ranked badly costs the turn one less useful paragraph. A
wrong ship-claim reading would raise or suppress a challenge, a wrong stagnation reading would change what the
agent is told to do next, and a wrong narration reading would block or pass a comment. Those are decisions an
operator lives with, so they stay with the rule that can be read and reasoned about. The model's own jaggedness
page says it does not treat its state as hostile; every one of these states is text the agent wrote.

**Pinned lessons are never reordered.** [/decisions/ad-043.md](/decisions/ad-043.md) exists because an operator's
standing rule lost a ranking it should never have been in. A model's relevance score is one more ranking.

**One block with four switches, not four capabilities.** Each use sends something different off the machine, and
that is a reason for four switches. It is not a reason for four keys, four budgets and four doctor rows. The
consent is per use; the plumbing is shared.

**A transport of its own, because the second caller arrived.** With one caller the key lookup and the budget lived
in the judge. A lesson ranker importing them from `src/core/untrusted/` would make the untrusted-content rail a
dependency of lessons, comments and stagnation, which have nothing to do with untrusted content.

## Trade-offs

**Four more kinds of data leave the machine, and that is not revertible.** Gate output is test and compiler
output, which quotes source. A reply can quote anything in the session. The catalog entry says which use sends
what, because the consent being asked for is per use.

**Latency lands on hooks that did not have any.** `stop` gains up to one `timeoutMs` per advisory call, and a gate
failure with both `stop` uses on makes two calls in sequence. The reply hook and the edit hook gain one each. All
of it is zero with the block off.

**`record` costs money and changes nothing.** That is the judge's trade-off again, and deliberate again.

**The stagnation advisor keeps gate output on disk.** One tail per session, under the project state directory,
written only while the use is on and overwritten on the next failure.

**Twelve lessons and six comments are constants.** Nobody has tuned them; they bound one hook's spend.

**The comment advisor only sees what the rule flagged.** It can measure the rule's false positives and not its
misses. Asking about every added comment would measure both and cost a request per comment per edit.

## Not decided here

- **Whether any use but `lessonRank` should ever apply.** That is what the records are for.
- **Thresholds.** `record` needs none. `apply` on lessons orders by the reading and uses no cut-off.
- **A relevance ranking at session start.** There is no prompt yet when lessons are injected there, so there is
  nothing to be relevant to. It would need the lessons to move to the first prompt.
- **An abstract interface with a second model behind it.** The judge's own open question, unchanged.
